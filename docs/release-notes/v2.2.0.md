## ScanEzi 2.2

The scanner's own Scan button now works the way it does with HP's software: press it, get a scan,
whether or not the ScanEzi window is open. ScanEzi keeps running in the notification area so it can
keep listening.

### What's new

- **ScanEzi stays in the notification area.** Closing the window no longer ends the app: it hides to
  the tray, where a ScanEzi icon stays available. Left-click it (or launch ScanEzi again) to bring the
  window back; right-click for **Open ScanEzi**, **Scan now** and **Quit ScanEzi**. The icon's tooltip
  shows the version, whether the scan-button listener is live, and how many pages are waiting.
- **The hardware Scan button keeps working while ScanEzi is hidden.** The listener is registered for
  the life of the process, so pressing Scan on the scanner starts a scan and the pages are waiting in
  the gallery when you open the window again. A tray notification confirms the first time the window
  is hidden so the app is not "missing".
- **Listener status in Settings.** A new **SCAN BUTTON** section shows whether the listener is
  registered (and how many scanner events it subscribed to) and lets you turn the tray behaviour off
  with **Keep running in the tray**.
- **One copy at a time.** Launching ScanEzi while it is already in the tray brings the existing window
  forward instead of starting a second process, so the scan button is never registered twice.

### Notes

- Prefer the old behaviour? Turn off **Keep running in the tray** in Settings: closing the window then
  exits ScanEzi, and the hardware Scan button only works while the window is open.
- Tray notifications respect Windows notification settings; if notifications are off, ScanEzi simply
  stays quiet in the tray.
- The installer is still per-user and unsigned, so SmartScreen may warn on first run.

### Upgrading

Installed copies update themselves: ScanEzi checks GitHub Releases on launch, offers 2.2 and applies
it on restart. You can also download `ScanEzi-2.2.0-setup.exe` and run it over the existing install.
Portable copies can either be replaced by unzipping the new build or updated in place from inside the
app.

Because the update restarts the app, the single-instance check is bypassed during an update: the old
process exits fully before the installer runs.
